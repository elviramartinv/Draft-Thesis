\chapter{The \textsc{HH-BTag} and \textsc{VBFjTag}}
\label{ch:taggers}
%
The final state $HH\rightarrow bb\tau\tau$, on which the analysis described in Chapter \ref{ch:bbtt_analysis} is based, consists of two composite objects: the $H\rightarrow\tau\tau$ candidate and the $H\rightarrow b\bar{b}$ candidate. Reconstructing these objects involves two distinct steps. The first step is identification, which involves determining the type of object based on its intrinsic properties. This includes both the identification of $\tau$ leptons, discussed in the preceding Chapter \ref{ch:Tau}, and the flavor classification of jets using standard CMS algorithms, introduced in Section \ref{subsec:Jets}. The second step is assignment, which determines which of all the identified candidates corresponds to the targeted final state. For the $H\rightarrow\tau\tau$ candidate, this decision is made using an explicit ordering criterion based on the isolation and transverse momentum of the candidates, described along with the rest of the selection in Chapter \ref{ch:bbtt_analysis}. Meanwhile, the jets that comprise the $H\rightarrow b\bar{b}$ candidate require dedicated treatment, which is the subject of this chapter.

In vector boson fusion production, a second pair of jets is added to these two jets in the final state. This pair does not result from the decay of any Higgs boson, but rather constitutes the characteristic signature of the VBF production mechanism. Thus, jets in the same final state play two distinct roles, and their correct assignment, in both cases, requires dedicated approaches that take into account the unique characteristics of each case, whether they are jets from the $H\rightarrow b\bar{b}$ candidate or the characteristic jets of VBF production.

In the first case, although the standard CMS $b$ tagging algorithms effectively identify jets originating from $b$ quarks, this information alone is insufficient to determine which jets constitute the $H\rightarrow b\bar{b}$ candidate. The most straightforward strategy is to sort the jets according to their $b$ tagging score and select the top two. This approach, however, disregards crucial event information for the decision, such as the kinematics of the $H\rightarrow\tau\tau$ candidate, the missing transverse momentum, and the angular relationship between the jets and the $\tau\tau$ system. Consequently, in events with more than two genuine $b$ jets, whether arising from additional radiation in the initial or final state, or from backgrounds such as $t\bar{t}$ pair production, the flavor score alone does not provide any decision criterion.

The second case poses an even greater challenge to standard CMS identification algorithms. Jets characteristic of VBF production originate from light quarks scattered at small angles and possess no intrinsic properties that distinguish them from jets arising from initial-state radiation or from QCD processes. Instead, these jets are characterized by the high invariant mass of the pair they form and their isolation from the rest of the hadronic activity; these properties apply to the pair as a whole and not to the individual objects. In both cases, therefore, the assignment requires dedicated strategies that use the information of the whole event rather than only that of each jet.\medskip

To address the issue of candidate assignment for $H\rightarrow b\bar{b}$ in the $HH\rightarrow bb\tau\tau$ analysis, \textcolor{red}{CMS} developed a classification algorithm called \textsc{HH-BTag} \textcolor{red}{\cite{CMS-HIG-20-010,HHBTag}}\textcolor{red}{[No se si puedo citar el AN]}. It consists of a recurrent neural network that assigns a score to each jet in the event based on how compatible it is with the hypothesis that the jet originates from Higgs decay. It was originally designed for the nonresonant $HH\rightarrow bb\tau\tau$ analysis of the Run 2 data \cite{CMS-HIG-20-010}, and has since been used in the search for resonant $HH$ production with the same data \cite{CMS-PAS-B2G-24-011}, in the study of $ZZ$ and $ZH$ production in the $bb\tau\tau$ final state, which shares the signature of $HH$ production with a $Z$ boson in place of one or both Higgs bosons \cite{CMS:2026zzzh}, and in the Run 3 analysis presented in this thesis \cite{CMS-PAS-HIG-25-008}.


The starting point is therefore the \textsc{HH-BTag} algorithm. However, the architecture on which this algorithm is based does not encode any property specifically associated with $b$ quarks; rather, the particular nature of the problem lies solely in the definition of the reference truth used during training and the set of selected input variables. Thus, this scheme is reusable with a different truth definition and set of input variables, i.e., for any jet-process assignment problem. It is therefore natural to consider an analogous classification algorithm for assigning of VBF-characteristic jets on this same conceptual framework. This is the second original development presented in this thesis: the \textsc{VBFjTag} algorithm. This is the origin of the \textsc{VBFjTag} algorithm, which benefits from the classification performed by \textsc{HH-BTag} itself, operating in a chained manner within the analysis, as will be seen in Chapter \ref{ch:bbtt_analysis}.\medskip

This chapter describes both algorithms, which provide the jet assignment used in the $HH\rightarrow bb\tau\tau$ analysis of the following chapters, introducing the machine learning concepts only as they become necessary. Section \ref{sec:assignment} presents the jet assignment problem and its formulation as a supervised learning problem, Section \ref{sec:architecture} describes the architecture and training strategy common to both algorithms, and Sections \ref{sec:HHBTag} and \ref{sec:VBFjTag} detail the development of \textsc{HH-BTag} — including its versions for the Run 2 searches — and \textsc{VBFjTag}, respectively. The chapter closes with the role of both algorithms in the Run 3 analysis, their limitations and the extensions that the approach admits.\medskip


\noindent The retraining of \textsc{HH-BTag} for the Run 2 resonant search \cite{CMS-PAS-B2G-24-011}, its validation on $Z\to b\bar{b}$ decays for the study of $ZZ$ and $ZH$ production, including a dedicated retraining \cite{CMS:2026zzzh}, its retraining for the Run 3 analysis \cite{CMS-PAS-HIG-25-008}, including the revised definition of its ground truth, and the development of \textsc{VBFjTag}, used for the first time in that analysis, constitute the contribution of this thesis presented in this chapter.




\section{The jet assignment problem}
\label{sec:assignment}
%
The issue of assignment is not a novel one, and throughout the operation of the LHC, it has been addressed using various approaches. In the $HH\to bb\tau\tau$ searches, both assignments were originally resolved with explicit criteria, without any training, whose limitations motivate the approach developed in this thesis.\medskip

Regarding the $H\rightarrow b\bar{b}$ candidate, the $b$ tagging discriminant sorting strategy was first employed in the initial search for Higgs boson pair production conducted by CMS \cite{CMS-HIG-15-013}, using data at $\sqrt{s} = 8$ TeV, where the two jets with the highest CSV discriminant values \cite{CMS-BTV-12-001} were identified as Higgs boson decay products. This criterion was maintained during the initial Run 2 analyses \cite{CMS:2018bbtt}, with only the discriminant itself being updated according to internal CMS recommendations, so that improvements were concentrated on identification. However, this criterion is limited by its very nature, since the jet is scored separately from the rest of the event and the physics underlying the Higgs boson decay process. The study of these analysis results identified the selection of the $H\rightarrow b\bar{b}$ candidate as one of the least efficient steps in the analysis, thus motivating the development of dedicated tagging algorithms. This culminated in the \textsc{HH-BTag} algorithm, introduced in the non-resonant analysis of the complete Run 2 dataset \cite{CMS-HIG-20-010}, which is described in detail in the following sections, along with the performance improvement it introduces compared to the initial discriminant-based sorting.

The assignment of the characteristic jets of VBF production, on the other hand, has always been based on a purely kinematic criterion in accordance with the signature specific to this process. Therefore, candidates are sought among the jets remaining after the $b$-pair assignment, with $p_T > 30$ GeV and $|\eta| < 4.7$, where the VBF jet pair is selected from the jet pair with the highest invariant mass among all possible pairs—a criterion motivated by VBF topology. While this assignment is well-founded — since it is based on the kinematic criteria of the event — it does not identify the VBF jets themselves, but rather selects the configuration that most closely resembles the one typically exhibited by these jets. This strategy however does not account for the properties that characterize the VBF topology beyond the kinematics of the pair, such as the isolation of these jets from the rest of the hadronic activity of the event and their relative position with respect to other objects. In contrast to the review conducted for the assignment of the $H\rightarrow b\bar{b}$ candidate, this strategy was maintained throughout the complete analysis of Run 2 \cite{CMS-HIG-20-010}: the Run 3 analysis that forms the basis of this thesis \cite{CMS-PAS-HIG-25-008} represents the first modification to this procedure, involving the use of the \textsc{VBFjTag} discriminant, which will be detailed below.\medskip

%These explicit criteria, as well as their evolution toward trained algorithms, are not unique to the $bb\tau\tau$ channel: the same shift is found across the leading di-Higgs final states, although it has taken a different form in each of them. In $bb\gamma\gamma$, the VBF jet pair was likewise chosen as the one with the highest invariant mass, and the most recent iteration of the analysis replaces that rule with a network trained to classify every possible pairing among the leading jets of the event, which improves the fraction of correctly identified pairs by about 8\% \cite{bbggAN}. In $bb\bar{b}b$, where the combinatorics are considerably richer because all four jets play the same role, the two $H\rightarrow bb$ candidates are still built with an explicit rule — among the four jets with the highest $b$ tagging score, the pairing that minimizes the mass difference between the two candidates — which attains an accuracy of about 94\% for the standard model signal but falls to 74\% for anomalous values of the Higgs boson self-coupling; rather than resolving the ambiguity beforehand, that analysis supplies the properties of all the alternative pairings to a classifier built from transformer blocks \cite{CMS:2026znu}. Across final states, therefore, the assignment problem has driven a common movement away from fixed rules and toward architectures that decide from the configuration of the event as a whole.\\

\subsection{Formulation as a supervised learning problem}
\label{subsec:supervised}
%
Explicit criteria thus act on a property of each object or, at most, on a quantity built from the candidate pair, whereas the role of each jet is determined by the configuration of the whole event. The assignment is therefore formulated here as a supervised learning problem, in which a model is trained on simulated events where the correct assignment is known and learns to reproduce it from the global information of the event. As with any supervised learning problem, this approach requires defining the output of the model, the information it receives to produce it, and the reference — provided by the simulated \textit{ground truth} — against which that output is compared while its parameters are adjusted.\medskip

Starting with the output format, in the formulation adopted by the algorithms described in this chapter, the model assigns a separate score to each jet in the event so that the pair is constructed from the two jets with the highest scores. The output therefore includes one component for each jet, which allows the condition that exactly two of them occupy the desired role to be imposed. It should be noted that this is not the only possible formulation; an equally valid alternative would be to operate on pairs, constructing $N(N-1)/2$ combinations from $N$ jets in the event and evaluating each one. However, this is the approach adopted here, as it is derived directly from the original development of the \textsc{HH-BTag} algorithm \textcolor{red}{\cite{CMS-HIG-20-010,HHBTag}} upon which the present chapter is based.

Nonetheless, the score assigned to a jet is not solely dependent on its properties; rather, the information received by the model is based on both the identity variables of each jet and global event quantities. The kinematics and $b$ tagging score of every jet, the kinematics of the $H\rightarrow\tau\tau$ candidate, the missing transverse momentum, and the angular separations between any jet and the $\tau\tau$ system are some of the input variables for the model. The model also receives the complete set of jets in the event, so that the score for each jet is determined in the presence of the other candidates. The complete sets of variables used for each of the developed algorithms will be detailed in the corresponding sections.

Finally, the reference against which this output is calibrated requires associating \textit{truth} labels with the jets from the samples used in training. The information at the generator level is the key factor here for determining whether a given jet belongs to the sought-after pair; therefore, the model parameters can be determined by minimizing the discrepancy between the predicted score and the label. The definition of this label is therefore the truly crucial element of the problem, as it must encode the role that the jet plays within the event, and thus its construction requires a dedicated procedure.\medskip

Two consequences follow from this formulation. First, the truth label only exists in events that contain the sought-after decay, two $b$ jets or two VBF jets, so that both algorithms must be trained and evaluated on simulated signal, with a selection that ensures that the label can be defined (Section \ref{subsec:groundtruth}). Second, a pair is selected in every event, without any threshold, so that the performance cannot be characterized by an efficiency and a misidentification rate, as for identification discriminants (Chapter \ref{ch:Tau}), but by the fraction of events in which the selected pair is correct (Section \ref{subsec:metric}).

\subsection{Definition of the Ground Truth}
\label{subsec:groundtruth}
%
The definition of the label has undergone successive refinements since the initial version of the algorithm \textcolor{red}{\cite{CMS-HIG-20-010,HHBTag}}, based on performance studies conducted during each retraining round. This section describes its final form, as applied to the models trained for the Run 3 analysis, and mentions the earlier versions only where the change is conceptually relevant.

The starting point is the generator-level information available in the simulated samples used during training. In generator-level particles, it is straightforward to identify the $b$ quarks originating from the Higgs boson decay or the outgoing quarks characteristic of VBF production. This information must be linked to the objects on which the algorithm ultimately operates, that is, the reconstructed jets. Between these two extremes — generated particles and reconstructed jets — there is an intermediate step: the definition of jets at the generator level.

This intermedite step arises because the four-momentum of the quarks produced in the interaction does not adequately describe the object that the detector ultimately reconstructs, since fragmentation and hadronization distribute the initial energy among a set of particles whose angular distribution differs from that of the original quark. In order to make a comparison between objects of the same nature, jets at generator level are used; these are obtained by grouping the stable particles in the simulation using the same algorithm employed in the reconstruction, and thus constitute the generated analog of the reconstructed object.

The label construction thus consists of two successive pairings, which are illustrated in Figure \ref{fig:groundtruth}. First, the jets generated from the process of interest are identified by associating them with the corresponding quarks previously identified. Then, the correspondence between the selected generated jets and the reconstructed jets is established. Both pairings are established using angular proximity criteria, as depicted in the diagram. It should be noted that the original development of the algorithm followed a different approach in the first matching step described, constructing a specific object at the generator level such that the association was implicit \textcolor{red}{\cite{CMS-HIG-20-010,HHBTag}}. In the approach adopted here, however, the association is made through explicit matching, directly using the standard CMS set of generated jets.
%
%%% candidate pair selection
Criteria are also established to unambiguously select the two jets of interest. For the $H\rightarrow b\bar{b}$ candidate, the pair whose invariant mass is closest to the Higgs boson mass is selected, as corresponds to the two $b$ jets originating from the Higgs\footnote{It should be emphasized that using the known mass of the boson introduces no bias whatsoever, since the ground truth is involved only in the training of the model and never in the analysis of the data}. This selection replaces the one used in the original development of the algorithm, which was based on taking the two highest-energy generated jets. \textcolor{red}{In the case of VBF jets, it holds that there are always two generated jets associated with the outgoing partons of the hard process - revisar}.

%% overlap removal
In addition, overlaps are eliminated to ensure that a given jet is assigned to a single role: in the case of $b$ jets, angular separation is required from both $\tau$ candidates, and in the case of VBF-jets, angular separation is required from the $\tau$ candidates and the previously identified $b$ pair. This requirement is imposed at both the generator and reconstructed levels to guarantee the comparability of both sets.

% kinematic selection
All these steps operate on candidates that pass kinematic and quality requirements, which differ between the two algorithms, mainly in their angular coverage, much wider for VBF jets, and are given in Sections \ref{sec:HHBTag} and \ref{sec:VBFjTag} together with the preparation of the training samples. In addition, events in which the two objects are so close that they are not reconstructed as two distinct jets, a situation characteristic of high transverse momentum, are excluded from the training set of both algorithms, so that the label, and therefore the models, are defined only for resolved topologies.

The ground truth is therefore not a measurable property of the simulated event, but rather a constructed definition based on it. Two reasonable but distinct definitions of truth can assign different labels to the same events and, consequently, lead to different measured performance for the same model. The results of the Run 3 version presented in this chapter are all obtained with this definition and are therefore comparable with one another, while those of the earlier versions, shown in Section \ref{subsec:hhbtag_run2}, rely on the definitions in use at the time.\medskip


\subsection{The purity metric as performance evaluation}
\label{subsec:metric}
%
Since the pair is a relative choice among the candidates of each event, without any threshold that a candidate must pass, the performance requires a purity metric — instead of an efficiency accompanied by a misidentification rate —, defined as
%
\begin{equation}
P = \frac{N_{\mathrm{true}}}{N},
\label{eq:purity}
\end{equation}
%
where $N_{\mathrm{true}}$ is the number of events in which the pair selected by the algorithm matches the one designated by the ground truth, and $N$ is the total number of events, all of which contain the two true jets by construction of the samples (Section \ref{subsec:groundtruth}).\medskip

In practice, purity is measured by sorting the jets in the event according to the score assigned by the corresponding model, and checking whether the first two are labeled true. If so, the event contributes to $N_{\mathrm{true}}$. A visual representation of the process can be seen in Figure \ref{fig:purity}. It is therefore a strict, binary quantity at the event level, where both jets must be correctly identified; cases with a single correctly identified jet count the same as those where neither jet was correctly identified.\\

It is important to clarify the scope of this metric. Purity is a measure of the effectiveness of the algorithm in selecting the correct candidates from the available optiones, under the condition that the event contains the desired objects in a form that can be reconstructed. Accordingly, the contribution of the algorithm is isolated, deliberately excluding losses due to detector acceptance or reconstruction efficiency. The fraction of signal events in which the analysis ultimately reconstructs the correct candidate is thus broken down into these two terms: the probability that both objects are reconstructed and pass the selection, and the purity of the assignment once this condition is met. While the former is accounted for in the analysis through selection efficiencies, it is the latter that is put to the test here. Purity therefore quantifies the quality of the decision made, allowing for a meaningful comparison between classifiers.

From the definition itself, it also follows that the purity defined here cannot be evaluated on background samples, since if the event does not contain the sought-after decay, $N_{\mathrm{true}}$ is meaningless because the correct pair does not exist. This is not incompatible with the algorithm operating on background events, since by design it will always select two jets, even if neither of them originates from the decay of interest. The behavior of the tagger with respect to background is therefore examined by looking at the shape of the scoring distributions, which is particularly relevant for the task of distinguishing the signal from the background — a task that must be addressed later in the analysis.\medskip

The same metric is also used during training, to decide when to stop it (Section \ref{subsec:training}), and guided the optimization of the hyperparameters in the original development of the algorithm.\bigskip

\noindent With the problem, the reference against which learning takes place and the metric that evaluates the result defined, the next step is the model that learns the assignment and the procedure that fixes its parameters, both common to the two algorithms and discussed in the following section.

\section{A common architecture for jet assignment}
\label{sec:architecture}
%
According to the formulation of the supervised learning problem outlined in Section \ref{subsec:supervised}, the function whose parameters are estimated from simulated examples is, in this case, a neural network. Artificial neural networks, simply called neural networks (NNs), are parameterized functions capable of learning, from provided examples, the relationship between inputs and a desired output \cite{Goodfellow2016}. These functions are constructed from elementary units, called artificial neurons, which apply a linear combination to their inputs, determined by a set of adjustable parameters known as \textit{weights}, and followed by a nonlinear function called \textit{activation}. These units are grouped into layers, and by chaining several of them together, a function is obtained capable of representing relationships that none of them describes separately. Furthermore, layers are distinguished by the way their units connect to those of the preceding layer: in a dense layer, each unit receives all the outputs from the previous layer, while other types impose specific connections, tailored to the structure of the data they are to process. The behavior of the network is thus determined by two sets of quantities of different natures: adjustable parameters, which are determined during training, and the hyperparameters, which are set in advance and determine the structure of the network — such as the number of layers, their type, and the number of units in each — as well as the training procedure.

Training therefore consists of iteratively traversing the set of labeled examples, comparing at each step the output of the model with the ground truth label through a loss function that guides the adjustment of the parameters. Thus, in each iteration, the parameters are modified to reduce the value of the loss function. The size of that modification, and the way in which it is computed, are dictated by an optimization algorithm, or \textit{optimizer}, which is itself one of the hyperparameters fixed before the training begins. The examples are processed in batches, and each complete pass through the set is called an epoch. At the end of each epoch, the performance of the model is measured with the purity, which determines when the training stops (Section \ref{subsec:training}). A schematic representation of the training process is shown in Figure \ref{fig:training_loop}.

The design of the model is constrained by two properties of the problem. The number of reconstructed jets varies from one event to another, so that the network cannot depend on it and must produce a score for each jet, and, since the decision involves comparing the candidates with one another, the score of each jet must be informed by the presence and properties of the others.

Both conditions are adequately satisfied by a specific type of layer: the recurrent layer. This layer traverses the elements of a sequence one after another, always applying the same operation to them, so that a single set of parameters suffices for an arbitrary number of elements. In doing so, it also maintains an internal state that is updated at each step, so that the value produced for each element incorporates information from the preceding elements. The variant used here, known as LSTM (\textit{Long Short-Term Memory}) \cite{Hochreiter1997}, incorporates an additional mechanism that maintains this state stable throughout long sequences. Applying such a layer to the jets of an event requires, however, that they first be expressed as an ordered numerical structure carrying a fixed set of quantities per jet.

The recurrent architecture is not the only one that satisfies these conditions, but it is the one adopted in the original development of \textsc{HH-BTag}, and it is kept, with the same structure and the same values of its hyperparameters, in all the versions presented in this chapter. In any case, the central recurrent block does not constitute the entire network; dense layers also play a role, acting on each jet separately, as will be seen later.\medskip

\noindent With the conceptual framework established, the following sections provide detailed analysis of each of these elements: Section \ref{subsec:inputs} describes how the event is represented before being fed into the network; Section \ref{subsec:network} details its internal structure and how the final score is calculated; Section \ref{subsec:training} outlines the procedure used to determine its parameters; and Section \ref{subsec:featimp} describes diagnostics applied to the model once trained, which examine the behavior of the training itself and identify which of the variables it receives are actually used.

\subsection{Representation of the event}
\label{subsec:inputs}
%
To ensure the network can process all the information, it is necessary to define how the event is processed at its input, since the network does not operate directly on the reconstructed event, but rather on a representation of it. Therefore, it is essential to establish a method for translating the information of the event — that is, both the global variables and the ones associated with the set of jets of variable size and without intrinsic order — into an ordered sequence that the network can process. The decisions made during this translation affect the output of the network and therefore constitute the first step in defining the algorithm.

To impose an ordered numerical structure on the event, it is arranged as a table in which each row corresponds to a reconstructed jet, such that each row contains two quantities: properties specific to the jet, whether its kinematics or its flavor discriminant; and global event quantities, such as the kinematics of the $H\rightarrow\tau\tau$ candidate or the missing transverse momentum. These latter quantities are replicated identically across all rows, enabling the network processing each row separately to access to information about the entire event.

%y de las de los jets que le preceden en la secuencia. Que dependa además de los que le siguen es consecuencia de la normalización aplicada a la salida, y se verá al describir la arquitectura.

Given that the output of a recurrent layer is not invariant under permutations of its input, the order in which the jets occupy the rows is also part of the definition of the algorithm, i.e., two different orders of the same jets from the event would produce different scores. It is therefore necessary to establish a criterion preferably based on a property specific to each jet to ensure that the ordering is reproducible. It is natural to do so by considering the physical meaning in accordance with the task designated for each classifier. Accordingly, the logical choice for \textsc{HH-BTag} is to arrange the jets from highest to lowest $b$ tagging discriminant, whereas \textsc{VBFjTag} is based instead on ordering from highest to lowest $|\eta|$, according to the kinematic characteristics of the jets within the VBF topology\footnote {One might consider using the invariant pair mass as a characteristic variable of the VBF topology. However, sorting requires a value associated with each jet separately, and deriving it from a pair property such as $m_{jj}$ would require fixing the partner of each jet in advance, which is precisely what the algorithm must determine.}. Under this assumption, the jets occupying the first positions in the sequence are those a priori most compatible with the desired role: those most similar to a $b$ quark in one case and those most advanced in the other. This criterion is applied when preparing the training samples, and must be reproduced identically when the model is evaluated within the analysis, since it is part of the input the model expects to receive.

The table presented as a translation of the event must also be bounded, since, while the network is capable of processing the sequence it receives regardless of its length, events are not processed one by one, but rather in batches that are evaluated simultaneously. This requires that all events share the same format, so a common number of rows is established. This number is set to ten — a value large enough to ensure that no information is lost in any of the samples used — so that when there are fewer jets, the remaining rows are filled with zeros. To ensure that this artificial padding does not alter the result, a column is added to the table to serve as a validity indicator, with a value of one in the rows that actually correspond to a reconstructed jet, and zero in the others. This column does not serve as an input variable for the network, but rather as a mask, so that the empty rows are excluded from all stages of the calculation and their presence does not affect the scores assigned to the actual jets. The resulting representation is illustrated in Figure \ref{fig:input_tensor}.

After determining the representation in the form of an ordered table, one final step remains before passing the information to the recurrent layers of the network. The quantities that comprise such table span a wide range. Depending on the variable being evaluated, these ranges can extend from several thousand GeV, as in the case of a transverse momentum, to values bounded between zero and one, as would be the case with a discriminant. This disparity significantly  complicates the fitting process, as the variables with the largest scales tend to dominate the others. Therefore, it is necessary to establish comparable ranges among the columns, which is done using one of the following methods, depending on the specific variable being analyzed:
\begin{itemize}
    \item Variables with a narrow peak in their distribution: Standardized by subtracting their mean and dividing by the standard deviation. The result is truncated at five sigmas to prevent extreme values from skewing the fit.
    \item Variables defined over a bounded domain: Linearly rescaled to the interval $[-1,1]$.
    \item Variables expressed in an appropriate range, such as the $b$ tagging discriminant itself: No transformation is applied.
\end{itemize}
All three treatments bring the columns to values of order one, and the interval of the rescaled variables is centered at zero, like the standardized ones, which favors the convergence of the fit.


% All three treatments aim to achieve the same goal: ensuring that all columns reach the network with values of order one. The choice of a zero-centered interval for the rescaled variables is not arbitrary, since inputs distributed around zero promote the convergence of the fit compared to those with a constant sign, and it also places this group in a position comparable to that of standardized variables, which, by definition, are also centered at zero.

In practice, these operations are part of the network itself through the first two layers that comprise it. In this manner, the constants that define them are stored along with the network parameters, permitting the network to be applied directly to the untransformed values during analysis.\medskip

    \item \textbf{Standardization and rescaling.} These constitute the first two layers of the model, and their function is to bring each column of the table to a comparable scale, as described in Section \ref{subsec:inputs}. They operate on a value-by-value basis, leaving the layout of the table intact so the data passed to the subsequent layers retains the format of one row per jet.
    \item \textbf{Recurrent block.} This is the central stage of the network responsible for establishing relationships between the different candidates, and thus the one that gives the model the ability to make decisions through comparison. It consists of five LSTM layers, each with $74$ units, followed by batch normalization \cite{Ioffe2015}, which readjusts the values produced by each layer based on the batch statistics to keep the internal distributions under control. The output of one layer is not sent directly to the next; rather, it is concatenated with the preprocessed input variables, to create an expanded set that feeds the next layer. In this manner, all layers have access to the original variables and not just the representation constructed by the preceding layer. Figure \ref{fig:architecture} shows this re-injection of the input as the dashed line originating from the preprocessing block.
    \item \textbf{Dense block and dense output layer.} The dense layers reduce the representation obtained for each jet to a single value. The block consists of thirteen layers of fifteen units, each followed by batch normalization and using the sigmoid activation, $\sigma(z) = (1+e^{-z})^{-1}$, which maps any real number to a value between zero and one. While the structure of the block is fixed by the optimized hyperparameters, the final layer is fixed by the desired output format: a single unit, also with sigmoid activation, produces a value $s_j$ per row. This is the only dense layer not followed by batch normalization, since its value must retain the scale in which it is interpreted, and the sigmoid guarantees that it is positive and bounded, as required by the normalization that follows. Like the standardization and rescaling layers, the dense layers act on each row independently, so that the output of a row depends only on its own content.    
    \item \textbf{Masking and normalization.} In the final step of the network, the mask sets the values corresponding to the filler rows to zero, ensuring that they do not affect the subsequent steps. The remaining true jets are divided by their sum over the event and multiplied by two, so that the final score of each jet, $y_j = 2\,s_j / \sum_k s_k$, lies between zero and two, and the sum of all scores in a single event equals two. This factor is not arbitrary but stems from the nature of the problem, which is to identify the two true jets in each event. Therefore, normalizing to two ensures that the reference value for a genuine candidate is one, and values further from one reflect the extent to which the score is distributed among the other jets. It is worth noting that this operation is part of the model itself, rather than a post-processing step.
\end{enumerate}

% \item \textbf{Dense block and dense output layer.} The goal of the dense layers is to reduce the representation obtained for each jet to the form from which the score is read. The separation between the block and the final output layer is crucial for this step: while the structure of the block is determined by the hyperparameters fixed through optimization, the final layer is entirely determined by the desired output format. Starting with the block, it consists of thirteen layers of fifteen units, followed by batch normalization. All of these layers are followed by a nonlinear activation, which is what makes stacking them meaningful: without it, any succession of dense layers would collapse into a single linear transformation. The function used here is the sigmoid, $\sigma(z) = (1+e^{-z})^{-1}$, which maps any real number to a value bounded between zero and one. Next, the dense layer with a single unit, which also uses the sigmoid activation function, produces a value $s_j$ per row. This is the only dense layer that is not followed by batch normalization, since its value must retain the scale in which it is interpreted. The choice of the sigmoid in this final layer is tied to the normalization that follows: the score of each jet is divided by the sum over the event, and the activation must therefore return a strictly positive value.\footnote{While other activations share this property, the sigmoid in particular present the additional property of being bounded, so that the values entering the normalization lie in a fixed range.} The dense layers — including those within the block and the one at the end — are applied independently to each row of the table, as are the standardization and rescaling layers. The output corresponding to a row therefore depends solely on its content, without any influence from the others.


From the description above it follows that a score of the jet is related with those of the others in two distinct ways. The first is the recurrent block, which is the only stage in which information travels throught the sequence of jets. The second is the final normalization that takes place while the parameters are being adjusted: by setting the sum of the scores of the events to two, increasing the score of one candidate necessarily requires decreasing the scores of the others. If these mechanisms were omitted, the score of each jet would have no reference to the other candidates, which is precisely the limitation of explicit criteria that initially motivated the development of these algorithms.\medskip

\subsection{Training procedure}
\label{subsec:training}
%
With the network described, this subsection details the remaining elements of the training cycle of Figure \ref{fig:training_loop}, namely the events that feed it, the loss function that measures the discrepancy between the output and the label, how this measurement translates into a modification of the parameters, and when the process is considered complete.\medskip

%1) conjuntos y division
The labeled simulated events, described for each algorithm in Sections \ref{sec:HHBTag} and \ref{sec:VBFjTag}, are not used to train a single model, but two. The events are divided into two halves based on the parity of their event number, and a model is trained on each of these subsets. This allows each event to be evaluated with the model that has not seen it during training, in order to avoid potential biases. Concurrently, one-quarter of the events randomly selected within each case is set aside for validation, i.e., is not used to adjust the parameters but is instead used during the training process itself to measure the performance of the model on events that were not part of the training set.

%2) perdida y optimizador

Each training iteration — that is, each parameter update — is performed on a batch of one hundred events. The network generates a score for each of its jets, and these scores are compared with their labels using the loss function. It should be noted that the purity defined in Section \ref{subsec:metric} cannot fulfill this role. This is because it depends solely on the order of the scores and not on their value, which makes it a discrete quantity whose derivative with respect to the parameters is zero, thus making it incapable of providing any indication as to in which direction to modify them. Instead, binary cross-entropy \cite{Goodfellow2016} is used as the quantity to be minimized during training, which continuously penalizes the discrepancy between the score and the label, reaching its minimum when the two coincide.

% Guided by the loss function, the optimizer is responsible for adjusting the parameters; it determines how the value of that function translates into a specific change in each parameter. The magnitude of that change is dictated by the learning rate, whose value cannot be too large — since the model would oscillate without ever converging — nor too small, since the process will be excessively slow. The optimizer also incorporates a weight decay term, which penalizes large parameter values and thus limits overfitting. The optimizer used here is \textit{AdamW} \cite{Loshchilov2019}, with a learning rate of $10^{-3}$ and a weight decay of $10^{-2}$.\medskip

Guided by the loss function, the optimizer determines how its value translates into a specific change in each parameter, with a step size set by the learning rate. The optimizer used here is \textit{AdamW} \cite{Loshchilov2019}, with a learning rate of $10^{-3}$ and a weight decay of $10^{-2}$, a term that penalizes large parameter values and thus limits overfitting.\medskip



%3) criterio de parada


However, while loss serves as an auxiliary function for training, the criterion for determining when to end training is whether the model is meeting its objective. Purity is therefore used at this stage, as it is the metric defined to ensure the accurate assignment of jets by the model. It is also the more robust choice for this purpose, since the loss is an unbounded average that a few poorly scored jets can shift appreciably, whereas the purity only counts whether the decision taken in each event is correct. At the end of each epoch — once all training events have been processed — the purity obtained is evaluated on the set of events reserved for validation, so that the process stops when ten consecutive epochs have elapsed without that value exceeding the maximum reached so far, a number known as the \textit{patience} of the criterion. The parameters corresponding to the epoch in which the maximum was reached are the ones that define the final model. To narrow the search, a maximum of $1000$ epochs is also set; in practice, this limit is never reached, since the condition described above interrupts the process much earlier, as is expected in stable training behavior.\medskip

In AdamW the weight decay is applied directly to the parameters rather than through the loss function, so that it can be adjusted separately; its value was set by hand while examining the stability of the training.}.

Finally, it must be verified that the training proceeded as expected. To this end, the loss function and the purity are recorded at the end of each epoch, both on the events used for training and on those reserved for validation, and two aspects are examined. The first is the convergence of the fit, which requires both quantities to stabilize, so that the stop occurs once the improvement has been exhausted and not because of a fluctuation in the middle of an upward trend. The second is the agreement between the values obtained on the training and validation events, since a gap between them would indicate that the model has learned features specific to the training events rather than the general relationship it should capture. A training that meets both conditions shows that the hyperparameter configuration is adequate for the problem and the samples considered.



\subsection{Definition and use of the input variables}
\label{subsec:featimp}
%Entradilla
The model and the procedure that determine its parameters have therefore been established given a set of variables received as input. The selection of variables is not trivial in this type of problem. While incorporating additional variables can expand the available information, it also introduces a greater number of parameters that must be adjusted. Consequently, a larger set does not necessarily guarantee a better model. Distinguishing between the variables that are worth including is a task that requires a judgment call based on the discriminant power of each variable and its contribution to the model. To this end, based on the phenomenology of the process, the variables with the greatest discriminatory power between the sought-after candidates and the others are proposed. Subsequently, once the model has been trained, it is determined which of these variables are actually used, since the contribution of a variable is not a property of the variable itself, but rather of what the model does with it.\medskip

%El método
While the determination of the discriminant magnitudes is specific to each problem, the procedure for determining how they contribute to the model is common to both algorithms. Permutation importance \cite{Breiman2001} is the tool used for this purpose. This tool involves taking one of the input variables and randomly permuting its values across all valid jets in the dataset on which it is evaluated. This ensures that the values of the variable remain the same and its distribution across the dataset remains unchanged, so the network continues to receive values of the same type as those it encountered during training. However, the correspondence between each value and the jet to which it belongs is no longer preserved, so the variable no longer provides any information about the candidate in whose row it appears. The model is then evaluated again, and the importance of the variable is defined as the drop in purity relative to the value obtained without permutation. The same procedure is repeated for each variable, permuting only one at a time and always starting from the unpermuted input.

%Lectura de los valores
The result of the procedure will determine which variables contribute the most information to the model. Therefore, regardless of the information contained in the variable, the primary concern is whether the model has effectively utilized that information: the measure is always relative to the specific model on which it is performed. On the other hand, correlated variables share importance, as when one of them is permuted, the others continue to make up for part of what that variable contributed. Hence, a low importance score is not decisive, unless it is verified that the variable in question is not correlated with the others — which can be verified using the correlation matrix of the input dataset.

%Caracter iterativo - esto no
%According to this interpretation, a variable whose permutation does not significantly alter the purity and that is not correlated with any other variable in the set is a candidate for removal. If the model maintains its performance after the removal and retraining, the decision is finalized. The selection of the input set is therefore an iterative process of training, testing, and retraining; consequently, the truly useful variables can only be identified after the training procedure is complete.


The values obtained may be negative, indicating that the model performs marginally better when the variable is permuted. Far from being meaningless, these cases define the range of statistical fluctuation in the procedure: a value falling within that range is indistinguishable from zero and indicates a magnitude that the model does not utilize, while those that exceed it by a wide margin identify the values on which the decision is based.\medskip


%A variable whose permutation alters the purity by no more than that fluctuation, and which is not correlated with any other variable in the set, is therefore a candidate for removal. If the model maintains its performance after the removal and retraining, the decision is finalized. The selection of the input set is therefore an iterative process of training, testing, and retraining; consequently, the truly useful variables can only be identified after the training procedure is complete.\\

%Cierre
Besides guiding the choice of the input set, this measure also shows whether the variables on which the decision is based are those expected from the physics of the process. In the development of each algorithm, it will therefore be used to determine the selection of input variables and to document the information on which the model is based.



\section{The \textsc{HH-BTag} algorithm}
\label{sec:HHBTag}
%
So far, the shared elements in both algorithms have been identified: the event representation, the network architecture, the procedure for determining the network parameters, and the tools for examining the model once it has been trained. The distinguishing features of each algorithm are based on the specific processes they are designed to address. This section therefore discusses the specific elements of \textsc{HH-BTag}, whose purpose is to determine which of the reconstructed jets in the event constitute the candidate $H\rightarrow b\bar{b}$.

The starting point is the version developed for the di-Higgs analysis in the non-resonant final state $bb\tau\tau$ of the complete Run 2 dataset \cite{CMS-HIG-20-010}, where the algorithm was first introduced. The work presented here builds upon this version and has involved its retraining for the resonant search using the same Run 2 data \cite{CMS-PAS-B2G-24-011}, its validation for the study of $ZZ$ and $ZH$ production \cite{CMS:2026zzzh}, and its retraining for the Run 3 analysis \cite{CMS-PAS-HIG-25-008}, which constitutes the main focus of this thesis. While the network architecture has remained unchanged across the different versions, the changes stem from modifications to the problem conditions that vary with each data-taking period, as updates to the flavor identification algorithms, which serve as input variables, and the reconstruction conditions of the objects on which the algorithm operates. Concurrently, the new versions refine the definition of the ground truth referred to in Section \ref{subsec:groundtruth}, always in pursuit of the best performance.\medskip

The following subsections describe the process and the preparation of the training set, the input variables and the information the model extracts from them, and the performance achieved compared with the explicit criterion it replaces. Finally, its application to two searches performed with the Run 2 data is presented.

\subsection{\texorpdfstring{$H\to b\bar{b}$}{H->bb}: candidates and training set}
\label{subsec:hhbtag_dataset}
%1- fisica
The $H\to b\bar{b}$ channel — the dominant decay mode of the Higgs boson — produces two $b$ quarks emitted back-to-back in the rest frame of the Higgs boson, whose kinematics in the laboratory is determined by the momentum of the boson. Their identification as $b$ jets relies on the displaced tracks and secondary vertices of the $b$ hadrons (Section \ref{subsec:Jets}), and is therefore restricted to the acceptance of the tracker, so that the problem is defined within $|\eta| < 2.5$.\medskip

%2 - seleccion
The candidate jets are those reconstructed within that angular window with a transverse momentum $p_T > 20$ GeV — which is the lowest threshold to which the jet and its flavor discriminant are calibrated — that also satisfy the jet identification quality criteria associated to each data-taking period. They are also required to have an angular separation of $\Delta R > 0.5$ from the two candidates that form the $\tau\tau$ pair, since the decay products of the $\tau$ particles can themselves be reconstructed as jets and compromise the set. Finally, at least two jets must satisfy these requirements to ensure that the $H\rightarrow b\bar{b}$ candidate can form.\medskip

%3 - muestras
Regarding the samples used, the training set is constructed exclusively from simulated samples of the $HH\to bb\tau\tau$ signal, given that the reference label can only be defined for events containing the sought-after decay, as discussed in Section \ref{subsec:supervised}. In each retraining run, the signal samples comprise all available productions in each corresponding data-taking period. Thus, when available, they include resonant production, generated for spin-0 and spin-2 hypotheses in a mass range from $250$ to $3000$ GeV; and non-resonant production, which, in addition to the SM case, includes various BSM reference models. The mix of samples used in the dataset allows the algorithm to cover a wide range of kinematic configurations, thereby preventing the model from specializing in a specific regime and becoming biased toward a particular signal hypothesis.

Therefore, the specific samples vary among versions of the algorithm. They depend on the availability of each data run, and other elements of the dataset preparation change accordingly, based on the recommendations associated with each data run, which are listed in Table \ref{tab:hhbtag_versions}. The initial version used all available simulated signal, including both gluon fusion and vector boson fusion. The second version, developed in this work for the Run 2 resonant search, was retrained on the Ultra-Legacy reprocessing of the Run 2 samples, \textcolor{red}{again with both production modes}, and its performance is presented in Section \ref{subsec:hhbtag_run2}, together with its validation for the study of $ZZ$ and $ZH$ production. The third version is the one developed for the partial analysis of Run 3 presented in this thesis, which also utilizes the available ggF and VBF production modes. The table outlines the evolution of the types of reconstructed jets\footnote{Run 2 used AK4 jets with charged hadron subtraction (CHS), complemented at low $p_T$ by a dedicated pileup jet identification, while Run 3 uses PUPPI jets, in which pileup is mitigated at the particle level (Section \ref{subsec:Jets}).} and consequently of the flavor discriminant appearing in the input variables, \textsc{DeepJet} \cite{Bols:2020bkb} in Run 2. Within Run 3 the discriminant is updated once more: \textsc{ParticleNet} \cite{PNet} is used for the 2022 and 2023 periods and \textsc{UParT} \cite{Qu:2022mxj,CMS-UParT} for 2024, following the recommendation issued for each of them. It is also important to note that the base selection inherited from the corresponding analysis differs between versions, directly impacting sample composition.\medskip




% 5 - ground truth 

The ground-truth label is then constructed from these samples according to the general procedure described in Section \ref{subsec:groundtruth}, with the necessary adaptations for this process. The generated jets associated with the $H\to b\bar{b}$ decay are subject to the same kinematic thresholds and the same separation of candidates $\tau$ as their reconstructed counterparts, to ensure the comparability of both sets. It is also required that there be exactly two generated jets that satisfy these conditions, and the correspondence with the reconstructed jets is established by requiring $\Delta R < 0.3$ between them. The event is only accepted if at least two pairings are successful. The collimated configurations excluded in this way (Section \ref{subsec:groundtruth}) are treated in the analysis with large-radius jets (Chapter \ref{ch:bbtt_analysis}). The statistics for the resulting events for each version after the entire specific selection process are shown in Table \ref{tab:hhbtag_versions}.\medskip

\subsection{Definition and assessment of the input set}
\label{subsec:hhbtag_inupts}

For each candidate jet, the network receives a set of quantities organized according to the structure described in Section \ref{subsec:inputs}: those that characterize the jet itself occupy the specific columns of its row, while those that describe the event as a whole are replicated identically across all rows. This set was not determined in the present work, but rather stems from the original development of the algorithm, in which various high-level quantities were investigated and those found to be the most discriminating ones were retained \cite{HHBTag}.\medskip

The \textsc{HH-BTag} algorithm uses fourteen variables, listed in Table \ref{tab:hhbtag_inputs} and grouped into four categories that follow from the phenomenology described in the previous subsection. The kinematics of the $\tau\tau$ candidate and the missing transverse momentum provide the context of the event and constrain the kinematics of the $H\rightarrow b\bar{b}$ candidate, while the angular distances between the jet and the $\tau\tau$ system turn the relationship between them into a quantity that the model can use directly. Finally, the global variables — the data-taking period and the reconstructed final state of the $\tau\tau$ pair — allow a single model to cover different experimental conditions and channels without training a separate model for each combination.

The kinematic variables were chosen to be independent of the specific signal scenario — resonant or nonresonant, mass, spin — so that the model could cover the entire phase space of the processes under consideration. The set has been retained in its original form, with the exception of the various recommendations regarding the flavor discriminator, which was replaced when the jet collection was changed.\medskip

Four measures clearly stand out from the rest. As expected, the flavor discriminant occupies the top position of the list, given its unique role as the sole variable that directly provides information about the flavor of the candidate. It is closely followed by the jet kinematics, as measured by the pseudorapidity and transverse momentum, and its azimuthal separation from the $\tau\tau$ system, whose discriminative power was evident in Figures \ref{fig:hhbtag_inputdist_jet} and \ref{fig:hhbtag_inputdist_ang}. The remaining variables rank one or two orders of magnitude below these top four, either because they are redundant in the cases already noted or because of their limited contribution to the model. The redundancy between inputs is made explicit in Figure \ref{fig:hhbtag_corr}, which shows their linear correlation coefficients and, as anticipated in Section \ref{subsec:featimp}, must be read together with Figure \ref{fig:hhbtag_featimp}, \textcolor{red}{comentar cuando la incluya}.

The hierarchy reflects two conditions that a variable must meet to be important, namely that it varies among the jets of the same event and that it provides information that cannot be recovered from the other inputs. The four dominant quantities meet both, three of them describing the jet itself and the fourth relating it to the rest of the event. The quantities of the $\tau\tau$ system and the missing transverse momentum fail the first condition, since they are replicated in all rows (Section \ref{subsec:inputs}) and cannot alter the order of the candidates on their own, and the redundant quantities fail the second, however marked the separation between their distributions (Section \ref{subsec:featimp}). Finally, the $\tau\tau$ decay channel and the \textcolor{red}{data-taking year} are completely transparent to the model, so that the assignment behaves uniformly across final states and years, as expected of an algorithm intended to be applied equally to all of them.\medskip


The study has been repeated in each of the retraining runs, and the results obtained are always consistent with one another; therefore, only those corresponding to \textcolor{red}{version v3} are presented here. The fact that the hierarchy remains unchanged when changing the samples, the data collection conditions, and the discriminant itself indicates that the model is based on the physics of the process and not on the particular characteristics of a specific dataset.

\subsection{Application to the Run 2 searches}
\label{subsec:hhbtag_run2}

The performance presented so far corresponds to the version retrained for the Run 3 analysis, whose role in the selection of the events and in the extraction of the signal is described in Chapter \ref{ch:bbtt_analysis}. Before this retraining, \textsc{HH-BTag} was adapted in this work to two searches performed with the Run 2 data in the same final state, the search for resonant $HH$ production \cite{CMS-PAS-B2G-24-011} and the study of $ZZ$ and $ZH$ production \cite{CMS:2026zzzh}. Beyond their own results, both put the algorithm to the test outside the conditions under which it was originally developed, the first over a much wider range of kinematic configurations and the second when the $b\bar{b}$ pair is produced by a different boson.

For the resonant search, the algorithm was retrained with the Ultra-Legacy reprocessing of the Run 2 simulation, which defines the version v2 of Table \ref{tab:hhbtag_versions}. The training set combines nonresonant production, for the SM and the BSM benchmark models, with the production of the spin-0 radions and spin-2 gravitons predicted by models with warped extra dimensions (Section \ref{subsec:BSM_production}), with masses between $250$ and $3000$ GeV, \textcolor{red}{through gluon fusion and vector boson fusion}. The ground truth already selected the pair of generated $b$ jets with the invariant mass closest to the Higgs boson mass and matched them to the reconstructed jets within $\Delta R < 0.3$, but it identified the generated $b$ jets through their parton flavour, without the explicit matching to the $b$ quarks from the Higgs boson decay adopted for Run 3 (Section \ref{subsec:groundtruth}). For nonresonant production, the purity ranges from $93.3$ to $95.9\%$, compared with $92.8$--$95.1\%$ and $89.0$--$90.2\%$, respectively.

The gain of the retrained version over the original one is smaller but systematic, and it is obtained with the same architecture and inputs by adapting the model to the reprocessed samples, which is the same reason that motivated its retraining for Run 3. \section{The \textsc{VBFjTag} algorithm}
\label{sec:VBFjTag}
%
In the $HH\to bb\tau\tau$ analysis, the jets from the event play two distinct roles: while some reconstruct the $H\to b\bar{b}$ decay, others identify the vector boson fusion production topology. Now that the assignment of candidates for the first of these problems has been resolved in a satisfactory manner, it is natural to implement the same procedure for the second, ensuring that the selection of all jets involved in the analysis relies on the same type of algorithm and follows the same criteria. This initiative led to the development of the \textsc{VBFjTag} algorithm, which was developed in this work and applied for the first time in the analysis presented in Chapter \ref{ch:bbtt_analysis} \cite{CMS-PAS-HIG-25-008}.

The architecture and the training procedure of Section \ref{sec:architecture} are reused without any modification, so that only the two elements that define the problem change. The first is the definition of the ground truth, which follows from a different phenomenology, since the jets of interest no longer arise from the decay of a particle but from the two scattered quarks that accompany the production of the Higgs boson pair. The second is the set of input variables, which must be reviewed to determine what information the model can use to learn under these new conditions.\medskip

Given the analogy between the two algorithms, this section follows the structure of the previous one and evaluates the results with the same criteria, so that both can be compared on the same footing.

\subsection{The VBF topology : candidates and training set}
\label{subsec:vbf_dataset}
%
% 1 - fenomenología
As described in Section \ref{subsec:SM_production}, the two quarks that radiate the vector bosons in VBF production give rise to two jets emitted close to the beam direction, with a large invariant mass and a large separation in pseudorapidity, on either side of the central $HH$ system. In addition, the exchanged bosons carry no color, so that the hadronic activity between the two jets is suppressed. These jets are therefore far apart from each other and isolated from the rest of the event, the two properties that the algorithm has to exploit.\medskip

% 2 - consecuencia para el problema de asignación
This phenomenology frames the problem in terms that differ significantly from those of the $H\to b\bar{b}$ channel. In that case, the most important variable for the model was an intrinsic property of the sought-after object: its flavor. In contrast, a VBF jet originates from a light quark and shares no distinguishing properties with the jets produced by radiation in any other process. The identification algorithms described in Section \ref{subsec:Jets} provide, along with the probability that the jet originates from a $b$ quark, analogous outputs for the $c$ quark or for a hadronic $\tau$, but none of them recognizes a VBF jet, so that they could only serve to rule out other hyptheses. The only hint carried by the jet itself the separation between jets initiated by quarks and those initiated by gluons, given that the other jets in the event are predominantly of gluonic origin. This separation is, however, considerable weaker than that of heavy flavor. At the same time, these discriminants rely on the tracks of charged constituents, so their performance degrades beyond the acceptance of the tracker detector, precisely in the angular region where VBF jets are abundant. The discriminating information must therefore be sought in the position of the jet and its relationship to the rest of the event rather than in the object itself.\medskip


% 3 - selección de candidatos
The candidates among which the VBF pair is sought are derived from those on which the kinematic criterion of Run 2 operated (Section \ref{sec:assignment}). In accordance, the algorithm is designed to be chained with the \textsc{HH-BTag} algorithm, so that it operates on the reconstructed jets after the other objects in the event have been processed. Candidates are selected by requiring a transverse momentum $p_T > 20$ GeV and a pseudorapidity $|\eta| < 4.7$, which covers the full acceptance of the calorimeter. Since it operates at the end of the processing chain, an angular separation of $\Delta R > 0.5$ is also required with respect to the two candidates forming the $\tau\tau$ pair and the two jets assigned to the $b\bar{b}$ pair. \textcolor{red}{Se descartan además los candidatos situados en la región $2.5 < |\eta| < 3.0$ con $p_T < 50$ GeV, donde ....?}. Furthermore, at least two jets must meet these criteria for the fusion pair to be formed.


%La ventana angular era la misma, pero el umbral en momento transverso se situaba entonces en 30 GeV; aquí se rebaja a 20 GeV, lo que amplía el conjunto sobre el que se decide sin comprometer la elección, pues el algoritmo ordena en lugar de cortar y un candidato adicional no es una contaminación, sino una alternativa más que la red ha de descartar.

%Es importante señalar aquí que aunque los dos jets asignados al par $b\bar{b}$ quedan excluidos de la elección de \textsc{VBFjTag}, si se figuran en el tensor de entrada, donde se identifica a cada uno de ellos mediante una variable que señala su condición. Tanto el bloque recurrente como la normalización de las puntuaciones acoplan entre sí todos los jets del evento, de modo que retirarlos privaría al modelo del contexto en el que ha de decidir.

% 4 - Muestras
In this case, the training set is limited to simulated production samples from the vector boson fusion of the Higgs boson pair, corresponding to the data-taking periods of early Run 3 (2022 to 2024). As previously explained, the sample mix includes the full range of coupling points $(\kappa_\lambda, c_{2V}, c_V)$ available, in order to ensure that the model covers a wide range of kinematic configurations without specializing in any one. In all cases, this involves non-resonant production, \textcolor{red}{por disponibilidad? o por que no quisimos incluir resonante?}. It should be noted that the restriction to this production mode is, once again, motivated by the need to define the ground truth. However, as with the \textsc{HH-BTag}, the algorithm is applied to all events in the analysis, so events produced by gluon fusion are treated as just another background in this context.

% 5 - Ground truth
Given the problem at hand, the definition of the true label is now based on the matrix element itself. Among the partons in the final state of the hard process, the two that are neither Higgs bosons nor $b$ quarks are identified, and which therefore correspond to the scattered quarks from the fusion vertex. These are associated with the nearest generated jet, requiring $\Delta R < 0.4$, equal to the radius at which the jets are reconstructed. The generated jets are then matched with the reconstructed jets that pass the candidate selection, within a cone of $\Delta R < 0.3$, such that only when both pairings are successful is the event labeled and admitted into the training set. An additional requirement at the generation level restricts the sample to resolved configurations and to those in which the $b\bar{b}$ pair and the $\tau\tau$ system are themselves well-defined, ensuring that the assignment is learned from events in which the entire topology of the process is present.\medskip


\subsection{Extending the input set}
\label{subsec:vbf_inputs}
%
% 1 - el tensor
The jets that meet the specified selection criteria form the rows of the table received by the network, ordered by decreasing $|\eta|$ (Section \ref{subsec:inputs}), so that the most forward jets head the sequence. The two jets assigned to the $b\bar{b}$ pair, although excluded from the selection performed by the model, are kept in the table to provide context and are identified by a dedicated variable.\medskip

% 2 - conjunto de variables
The starting point in this case is the set of fourteen variables used by \textsc{HH-BTag}, listed in Table \ref{tab:hhbtag_inputs}. While intended to address a different problem, the quantities that describe the context of the event — such as the kinematics of the $\tau\tau$ system, the missing transverse momentum, and the global period and channel variables — characterize the event independently of the jet being evaluated and are therefore directly applicable here. Those that describe the jet itself and relate it to the $\tau\tau$ system also retain their relevance, although the weight the model assigns to them is not necessarily equivalent.

Figure \ref{fig:vbfjtag_inputdist_1} shows the distributions of the variables of the jets, separating those tagged as originating from the vector boson fusion vertex from the rest of the event candidates. The most notable contrast is seen in the transverse momentum and pseudorapidity, since the VBF jets are significantly more energetic than the radiation that populates the set of candidates.... \textcolor{red}{Tengo que sacar la figura}

% La energía normalizada al momento transverso acompaña a esta última, en virtud de la relación señalada en la Sección \ref{subsec:hhbtag_inputs}, y el discriminante de sabor se acumula para los jets de fusión en los valores bajos, como corresponde a un quark ligero.\\



Three quantities are incorporated into this set that directly reflect the described phenomenology. As noted, the first indicates whether the jet has been assigned to the $b\bar{b}$ pair by \textsc{HH-BTag}, which provides the network with the result of the previous step in the chain and thus with the type of jets to be excluded from the selection. The second variable translates the suppression of hadronic activity resulting from the colorless nature of the exchange into a variable that measures the isolation of the jet, defined as the smallest angular separation between the jet and any other jet in the event. The third variable measures the relative position of the jet within the event using centrality, defined as:
%
\begin{equation}
\mathcal{C}_j = 1 - \left| \frac{2\,(\eta_j - \eta_c)}{\eta_{\max} - \eta_{\min}} \right| ,
\qquad \eta_c = \frac{\eta_{\max} + \eta_{\min}}{2},
\label{eq:centrality}
\end{equation}
%
where $\eta_{\max}$ and $\eta_{\min}$ refer to the extreme values of pseudorapidity among the jets in the event. This variable takes the value of one for a jet located at the center of the interval and vanishes at its ends, so that a VBF jet — which, by definition, occupies one of the edges — is characterized by values close to zero. Unlike bare pseudorapidity, centrality expresses the position of the jet relative to the angular extent of the event itself, rather than relative to the reference frame of the detector.

Other quantities suggested by the phenomenology or by similar studies in the $HH\to bb\gamma\gamma$ analysis \cite{bbggAN} were also examined, namely the quark-gluon discriminant, the jet multiplicity of the event and the transverse momentum of the two leading jets normalized to the invariant mass of the pair, but they were not retained, since they did not improve the purity (Section \ref{subsec:vbf_performance}). Both the retained and discarded quantities are listed in Table \ref{tab:vbfjtag_inputs}.

\noindent This chapter has described \textsc{HH-BTag} and \textsc{VBFjTag}, two algorithms that assign the jets of the event to the $H\to b\bar{b}$ candidate and to the VBF topology, respectively, and that substantially and consistently improve upon the explicit criteria they replace. The retraining of the first for the Run 2 resonant search \cite{CMS-PAS-B2G-24-011}, its validation for the study of $ZZ$ and $ZH$ production \cite{CMS:2026zzzh} and its retraining for Run 3 \cite{CMS-PAS-HIG-25-008}, together with the development of the second, constitute the contribution of this thesis presented here. Both share the event representation, the architecture, the training procedure and the evaluation tools, and differ only in the process they describe. To conclude, the following paragraphs outline their role in the $HH\to bb\tau\tau$ analysis, the limits that lie beyond their reach and the extensions that the approach admits. \textcolor{red}{hacer una seccion de esto???}\medskip


In the analysis of Chapter \ref{ch:bbtt_analysis}, \textsc{HH-BTag} selects the $H\to b\bar{b}$ candidate in the resolved topology, determining the invariant mass of the $H\to b\bar{b}$ system and the categorization of the events. Its score is also provided to the classifier that extracts the signal as a high-level variable associated with each candidate. By contrast, \textsc{VBFjTag} selects the jet pair on which the VBF category is defined, but its score is not used as a discriminant in the current Run 3 analysis strategy, which leaves room for future improvement in order to take advantage of the discriminating power it has demonstrated in the study presented here.

As noted in Section \ref{subsec:metric}, the purity excludes the losses in the reconstruction of the sought-after objects, which no assignment algorithm can recover. In the case of the pair $b\bar{b}$, this consideration poses little of a problem, as the reconstruction rate is often high. However, it is notably lower in the case of VBF jets, whose reconstruction is compromised by their location in the forward region of the detector, where the resolution is poorer and the contribution from pileup is greater. A perfect assignment algorithm would not remedy this loss, so an improvement in this regard would have to be pursued upstream, in the reconstruction of the object itself.

With regard to potential areas for enhancement, the training procedure followed in this study raise some open questions that can be explored in future iterations of the algorithm. First, it should be noted that the mix of samples in the training set includes processes with widely varying cross-sections and diverse kinematic configurations. Currently, the model does not incorporate a weighting mechanism to account for this; instead, all events contribute equally to the loss function. Further studies are necessary to examine the effect of weighting the samples on performance, particularly on the uniformity of performance across the coupling points. The hyperparameter configuration has also been carried over from the first developed version of \textsc{HH-BTag} to all subsequent versions, with the only change of the optimizer, including the problem addressed by \textsc{VBFjTag}. The convergence of the training shows that it remains adequate, but there is no guarantee that it is the best available. Therefore, reoptimization should be considered in light of the different conditions of the latest developments.\medskip

At the same time, the architecture itself admits improvements in line with the latest developments in machine learning for this type of problem. The recurrent block processes the jets as a sequence, thereby imposing an order on what is actually a set. This does not necessarily degrade the performance, as the results presented in this chapter attest, but it means that a property known a priori, namely that the result should not depend on the order of the jets, must be learned from the data rather than imposed by design, and that the output depends on an ordering criterion that has to be established and justified, even though the physics of the problem does not distinguish one jet from another by its position in a list. Only the final normalization is symmetric by design, and the question is whether this symmetry can be extended to the whole model.

Transformers \cite{Vaswani2017}, which currently serve as the standard architecture for structured data, possess this symmetry by construction, since without positional encoding their attention mechanism makes the output associated with each element a symmetric function of all the others, so that each jet would be evaluated against the other jets themselves and not against their position in the list. The approach is not new in this field, as the latest flavor discriminants developed by CMS, which the algorithm itself receives as input, belong to this family of architectures \cite{Qu:2022mxj,CMS-UParT}, applied to the constituents of a jet rather than to the jets of the event. Such a change would remove the asymmetry and make the ordering criterion unnecessary, while the format of the input and output, the ground truth, the purity metric, the input variables and the whole evaluation framework would carry over unchanged, so that studying it would only require retraining, reoptimizing the hyperparameters and revalidating the analysis chain.\medskip

Finally, it should be noted that the generality of this approach is not limited to the two problems solved here. Defining an algorithm of this family requires only two things: a reference truth that establishes which objects play the desired role in each simulated event, and a set of variables that describes the candidates and the event that contains them. Everything else is standard, as has been shown in the transition from the first problem to the second. The same construction is therefore applicable to the assignment of the pair $b\bar{b}$ in other final states of the $HH$ process, to the identification of the fusion signature of vector bosons in processes other than the one studied here, or, in general, to any reconstruction in which one must decide which objects correspond to a given decay chain.
